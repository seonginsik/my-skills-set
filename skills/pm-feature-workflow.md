# PM 기능 기획 워크플로우

> 이 파일은 `pm-feature-workflow` 스킬입니다.
> CLAUDE.md에서 "PM 기획 작업"으로 분류된 요청을 받으면 이 파일을 먼저 읽고 아래 순서를 따른다.
>
> **다른 기획 스킬과 나누는 기준:** 이 스킬은 **지표를 올리는 프로젝트**(전환율 · 이탈률 등 — 문제 확인 → 플로우 → PRD → 지표)를 설계할 때 쓴다. 서비스의 **기능 영역을 처음부터 기획**하거나(기능정의서 → 정책 → 프로토타입 → 화면설계 → 동작 웹) 결정을 여러 문서에 반영할 때는 `skills/product-planning-process.md`, 정책 문장을 쓰고 다듬을 때는 `skills/policy-doc-writing.md`를 쓴다. 이 스킬의 3단계 PRD가 승인되면 그 뒤 화면 · 정책 작업은 product-planning-process로 이어간다.

---

## 이 스킬을 쓰는 상황

- 신규 기능/정책을 기획할 때
- 전환율·이탈률 등 특정 지표를 개선하는 프로젝트를 설계할 때
- 예시 프로젝트: **신규 가입자 의뢰 전환율 상승**

---

## 진행 순서 (반드시 이 순서로, 단계를 건너뛰지 않는다)

### 1단계. 방향성 및 우선순위 정의

- 먼저 "왜 이 문제가 중요한가"를 숫자로 확인한다.
  - 예: 신규 가입자 중 몇 %가 첫 의뢰까지 도달하는가? 어느 단계에서 가장 많이 이탈하는가?
- **추측으로 우선순위를 매기지 않는다.** 근거 없이 "이게 문제일 것 같다"고 결론 내지 말고, 반드시 데이터(퍼널 지표, 유저 피드백, 고객센터 문의 등)로 뒷받침한다.
- 확인이 끝나면 "가장 이탈이 큰 지점 Top 3"와 "예상 임팩트"를 먼저 정리해서 사람(나)에게 보여주고, 어디부터 손댈지 확인받는다.

### 2단계. 서비스 유저플로우 수립

- 기존 유저플로우 문서/화면 구조를 먼저 확인한다. (없으면 나에게 물어본다)
- 신규 플로우안을 만들 때는:
  - 기존 대비 **변경되는 지점만 명확히 표시**한다 (Before/After 비교 형태).
  - 이탈 가능성이 있는 예외 케이스(에러, 중도 이탈, 재방문 등)를 빠짐없이 표시한다.
  - 신규 가입자 전환율 프로젝트라면, "가입 → 정보입력 → 의뢰서 작성 → 제출" 각 단계별로 이탈 포인트와 개선 아이디어를 함께 표시한다.
- 플로우 초안이 나오면 다이어그램/단계별 리스트 형태로 정리해서 보여주고 승인받는다.

### 3단계. PRD 작성

- PRD는 항상 다음 순서로 작성한다:
  1. 배경 (왜 하는가 — 1단계 데이터 근거 인용)
  2. 목표 (무엇을 달성하려는가 — 측정 가능한 문장으로)
  3. 요구사항 (무엇을 만드는가 — 2단계 플로우 기반)
  4. Acceptance Criteria (완료 기준 — 체크리스트 형태)
  5. 성공 지표 (4단계에서 정의할 지표와 연결)
- 모호한 표현 금지: "개선한다", "편의성을 높인다" 같은 문장 대신 "의뢰서 작성 완료율을 X%p 올린다" 처럼 구체적으로 쓴다.
- PRD 초안이 나오면 전체를 보여주고, 승인 전까지는 다음 단계로 넘어가지 않는다.

### 4단계. 핵심 지표 정의 및 데이터 분석

- 지표를 정의할 때는 반드시 다음을 명시한다:
  - 분자/분모 정확한 정의 (예: 분모 = 해당 기간 신규 가입자 수, 분자 = 가입 후 7일 내 의뢰서 제출자 수)
  - 집계 기간
  - 세그먼트 (전체 vs 특정 유입 채널 vs 특정 연령대 등)
- 가능하면 검증용 쿼리/분석 로직 초안까지 함께 만든다.
- A/B 테스트가 필요한 경우, 테스트군/대조군 분리 기준과 최소 샘플 크기까지 같이 정리한다.
- 결과 해석 시 "한 번의 결과만으로 판단하지 않는다" — 가능하면 세그먼트별 재현성을 함께 확인한다.

---

## 각 단계 공통 규칙

- 단계를 넘어갈 때마다 **사람 승인**을 받는다. 승인 없이 다음 단계로 진행하지 않는다.
- 각 단계 결과물은 `tasks/progress.md`에 요약해서 기록한다 (날짜 + 단계 + 결과 요약).
- 이전에 비슷한 프로젝트를 진행한 기록이 있다면(`projects/` 아래 지난 프로젝트 폴더, `tasks/progress.md`) 먼저 참고하고, 있으면 언급한다.

---

## 산출물 저장 위치

- PRD, 유저플로우, 지표 정의서는 `projects/<프로젝트명>/` 폴더에 저장한다.
- 예: `projects/signup-conversion/prd.md`, `projects/signup-conversion/user-flow.md`
