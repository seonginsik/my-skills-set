# 화면 문구(UX 라이팅) 스킬

> 이 파일은 `ux-writing` 스킬입니다.
> 화면 문구(버튼 · 안내 · 오류 · 결과 알림 · 빈 화면 · 확인 창 · 메일 제목)를 새로 쓰거나 고칠 때 먼저 읽고 따른다. 화면설계서 · 동작 시연 · 기능정의서의 따옴표 문구 예시에 똑같이 적용한다.
> 도메인 · 프로젝트와 관계없이 쓴다. **말투(주체별) · 용어집 · 연락처 같은 고정 문구**는 **프로젝트 폴더의 `planning-config.md` › '화면 문구'** 절과 그 절이 가리키는 프로젝트 문구 가이드에서 찾는다. 이 스킬에는 고유 이름을 적지 않는다.
> 대상이 아닌 것: 사용자와 나누는 대화(채팅) 말투, 시연 · 테스트 도구 글, 설계 보기(번호 설명) 글.

---

## 1. 원칙

1. **사용자의 말로 쓴다.** 기획 용어 · 내부 상태값 · 영문 약어보다 그 화면을 쓰는 사람이 일상에서 쓰는 말.
2. **주체(화면을 쓰는 사람)마다 말투를 하나로 정하고 섞지 않는다.** 설정 파일에서 고른다(예: 업무 화면 = 합니다체, 일반 사용자 화면 = 해요체).
3. **무엇이 일어났는지 + 다음에 할 일**을 함께 알린다. 오류에는 원인과 해결 방법, 빈 화면에는 다음 행동.
4. **짧게, 한 문장에 한 가지.** 안내는 한 줄(40자 안팎), 길면 두 문장으로.
5. **같은 것은 늘 같은 이름으로.** 용어집에 있는 말만 쓴다.

## 2. 말투 표 (설정 파일에서 주체마다 하나 고름)

| 상황 | 합니다체 | 해요체 |
|---|---|---|
| 안내 · 설명 | ~합니다 / ~됩니다 | ~해요 / ~돼요 |
| 부탁 · 입력 요청 | ~해 주세요 | ~해 주세요 |
| 결과 알림 | ~했습니다 | ~했어요 |
| 못 하는 것 | ~할 수 없습니다 + 이유 | ~할 수 없어요 + 이유 |
| 질문(확인 창 제목) | ~하시겠습니까? | ~할까요? |
| 상태 · 없음 | ~입니다 / ~없습니다 | ~이에요 / ~없어요 |

- 어느 말투든 쓰지 않는 것: 명령형 '~하세요', '~바랍니다', '~해 주십시오', 명사로 끝맺기('수정 불가', '등록 완료'), 느낌표 · 이모지.
- 사용자를 '고객님'처럼 부르지 않는다(설정 파일이 따로 정하면 그것을 따름). 주어는 되도록 뺀다.

## 3. 상황별 공식

| 종류 | 공식 | 예(합니다체) |
|---|---|---|
| 버튼 | 동사로, 결과가 보이게. [확인] 단독 금지(확인 창의 [닫기]는 예외). 확인 창 버튼은 제목의 동사 그대로. 되돌릴 수 없는 동작은 그 동작 이름 | [저장] [판매 시작] / "삭제하시겠습니까?" → [취소] [삭제] |
| 결과 알림 | (무엇을) ~했습니다 + 필요하면 다음 결과 한 마디 | 운영정보를 저장했습니다. 화면 아래쪽 정보에도 바로 반영됩니다. |
| 입력 오류 | 칸 아래에 짧게, 무엇을 고치면 되는지 | 이메일 형식을 확인해 주세요. |
| 막힌 동작 | 무엇이 안 되는지 + 어떻게 하면 되는지 | 판매 중인 상품은 삭제할 수 없습니다. 먼저 판매를 중지해 주세요. |
| 시스템 오류 | 다시 시도 + 계속되면 문의처 | 잠시 후 다시 시도해 주세요. 계속되면 고객센터로 문의해 주세요. |
| 빈 화면 | ~이 없습니다 + 다음 행동 버튼 | 아직 등록한 상품이 없습니다. [상품 등록] |
| 확인 창 | 제목 한 문장 질문 + 본문에 바뀌는 것 · 되돌릴 수 있는지 + [취소][동작] | 삭제하면 되돌릴 수 없습니다. 지난 주문 기록은 그대로 남습니다. |
| 안내 · 도움말 | 지금 알아야 할 것만 | — |

- 숫자는 아라비아 숫자, 단위는 붙여 쓴다(7일 · 20건 · 10MB · 30,000원). 날짜 `YYYY-MM-DD`(표에서는 `MM-DD`), 시간 `HH:MM`.
- 보안 · 개인정보 문구는 존재 여부를 드러내지 않는다(예: 로그인 실패는 어느 쪽이 틀렸는지 말하지 않음).

## 4. 화면에 쓰지 않는 것

| 쓰지 않는 것 | 대신 |
|---|---|
| 기획 표시(미정 번호 · 가정 표시 · 기능 ID · 정책 절 번호) | 지운다 — 기획 문서에만 |
| 내부 상태값 · 오류 코드 · '잘못된 요청' · '알 수 없는 오류' | 무엇이 안 됐는지 사용자 말로 |
| 명사 끝맺음 | 문장으로 (단, **상태 배지 · 표 머리 · 메뉴 이름은 명사 허용**) |
| 정한 말투가 아닌 말투 | 주체의 말투로 |
| 이중 부정 · 피동 | "~해야 ~할 수 있습니다" |
| 범위에서 뺀 기능 이야기('~는 지원하지 않습니다' 등) | 남은 기능만 안내 |

## 5. 고칠 때

- 한 화면을 고치면 같은 상황의 다른 화면(같은 버튼 · 같은 오류)도 같은 문구인지 찾아 맞춘다.
- 용어집에 없는 새 말이 필요하면 용어집에 먼저 더하고 쓴다(설정 파일이 가리키는 가이드).
- 기능정의서 · 화면설계 · 동작 시연의 같은 문구가 서로 다르면 기능정의서 → 화면설계 → 시연 순서로 맞춘다.

## 완료 전 점검표

- [ ] 주체의 말투 하나로만 썼다(섞임 0)
- [ ] 용어집 밖 말 0, 기획 표시 · 내부 코드 0
- [ ] 오류 · 막힘에 해결 방법, 빈 화면에 다음 행동이 있다
- [ ] 버튼은 동사, 확인 창 버튼 = 제목 동사
- [ ] 숫자 · 날짜 표기가 규칙대로다
