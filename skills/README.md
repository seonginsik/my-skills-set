# 기획 스킬 모음

AI(Claude Code)가 기획 문서를 **사람이 바뀌어도 같은 규칙으로** 쓰게 하는 스킬 8개입니다.
도메인 · 프로젝트와 관계없이 쓰도록 만들었고, 프로젝트마다 다른 값은 각 프로젝트의 설정 파일(`planning-config.md`)에 둡니다.

---

## 1. 스킬 목록

| 스킬 | 언제 쓰나 | 다루는 문서 | 프로젝트 설정 절 |
|---|---|---|---|
| `product-planning-process` | 새 영역을 기획할 때, 결정을 여러 문서에 반영할 때, 담당 간 일을 넘기고 대조할 때 | 전체 단계 순서(범위 → 정책 → 기능정의서 → LOFI → 화면설계 → HIFI) · 기획 ERD | 기획 프로세스 |
| `policy-doc-writing` | 운영정책 · 비즈니스 규칙을 쓰거나 다듬을 때, 기능을 범위에서 넣고 뺄 때 | 운영정책 · 유저플로우 | 정책 |
| `spec-sheet-writing` | 기능정의서를 새로 쓰거나 고칠 때, 기능을 뺄 때, 미정 질문을 관리할 때 | 기능정의서(엑셀 · 구글 시트 기본, 노션 데이터베이스 포함) | 기능정의서 |
| `screen-spec-writing` | 화면설계서를 만들거나 고칠 때, 화면을 보관할 때, 정리 · 점검할 때 | 화면설계서(피그마 기본) | 화면설계 |
| `ux-writing` | 화면 문구를 쓰거나 고칠 때 | 버튼 · 안내 · 오류 · 결과 알림 · 빈 화면 · 확인 창 | 화면 문구 |
| `qa-process` | 동작 시연 웹을 따로 검증하고 QA 보고서를 남길 때 | 정책 줄 대조표 · 결함 목록 · QA 보고서 | QA |
| `team-collaboration-process` | 기획자가 둘 이상이거나 디자인 · 개발 · QA가 합류했을 때 (설정에서 '적용 중'일 때만) | 분담 · 넘김 · 결정 권한 · 작업 줄 | 협업 |
| `pm-feature-workflow` | 지표(전환율 · 이탈률 등)를 올리는 프로젝트를 설계할 때 | 문제 확인 → 플로우 → PRD → 지표 | — |

## 2. 어느 단계에 어느 스킬

```
[지표 개선 프로젝트] pm-feature-workflow ──(PRD 뒤)──┐
                                                     ▼
범위 ─▶ 정책 · 유저플로우 ─▶ 기능정의서 ─▶ LOFI ─▶ 화면설계 ─▶ HIFI ─▶ QA
         policy-doc-writing   spec-sheet-writing       screen-spec-writing     qa-process
                                     └──────── ux-writing (화면 문구는 어디서나) ────────┘
전체 순서 · 결정 반영 고리 · 넘김: product-planning-process
여럿이 나눠 일할 때: team-collaboration-process
```

- 문서끼리 다르면 **정책 → 기능정의서 → 화면설계 → 동작 시연** 순서로 따릅니다.

## 3. 설치 · 등록

스킬 내용(원본)은 이 `skills/` 폴더에만 있습니다. Claude Code는 `.claude/skills/<이름>/SKILL.md` 모양만 스킬로 알아보기 때문에, 원본을 가리키는 짧은 **등록 파일**을 따로 둡니다.

```
저장소 맨 위/
├── skills/                       ← 스킬 원본 (이 폴더)
│   ├── README.md                 ← 지금 이 파일
│   ├── planning-config.template.md  ← 프로젝트 설정 빈 틀
│   └── <스킬 이름>.md × 8
└── .claude/skills/<스킬 이름>/SKILL.md   ← 등록 파일 (원본을 가리키는 6줄)
```

**이 저장소를 그대로 받은 경우:** 등록 파일이 이미 있어서 저장소 맨 위에서 Claude Code를 열면 바로 쓸 수 있습니다. 확인: Claude Code에서 `/` 를 눌러 스킬 목록에 8개가 보이는지.

**다른 저장소에서 쓰는 경우:**
1. `skills/` 폴더를 그 저장소 맨 위에 복사합니다.
2. 스킬마다 `.claude/skills/<스킬 이름>/SKILL.md`를 아래 틀로 만듭니다(경로는 상대 경로라 PC가 달라도 됩니다).

```markdown
---
name: <스킬 이름>
description: <언제 쓰는지 한두 문장 — 1절 표의 '언제 쓰나'>
---

이 저장소 맨 위의 `skills/<스킬 이름>.md`(이 파일 기준 `../../../skills/<스킬 이름>.md`) 를 읽고 따른다. 프로젝트마다 다른 값은 그 프로젝트 폴더의 `planning-config.md`에서 '<설정 절 이름>' 절을 찾는다. (내용의 원본은 그 파일 하나 — 여기서는 고치지 않는다.)
```

3. 스킬을 열 때 Claude Code는 저장소 맨 위에서 실행해야 상대 경로가 맞습니다.

## 4. 프로젝트 설정 파일 (`planning-config.md`)

- 프로젝트마다 그 프로젝트 폴더에 하나 둡니다. **절 이름 = 1절 표의 '프로젝트 설정 절'**.
- 넣는 것: 문서 위치(시트 · 화면설계 파일 · 공유 페이지 링크), 탭 번호, 기능 ID · 화면 ID 접두어, 컴포넌트 · 변수 이름, 용어 · 말투, 도구 명령, 보안 규칙, 협업 상태.
- 새 프로젝트는 [planning-config.template.md](planning-config.template.md)를 복사해 채웁니다. 기능정의서를 빈 문서로 시작하는 순서는 `spec-sheet-writing` 0-2절에 있습니다.
- 설정이 바뀌면 그 파일만 고칩니다. 스킬은 고치지 않습니다.

## 5. 스킬을 고치는 규칙

1. **원본은 `skills/<이름>.md` 하나.** 등록 파일(`SKILL.md`)에는 내용을 쓰지 않습니다.
2. **고유 이름을 쓰지 않습니다.** 프로젝트 · 서비스 · 회사 · 사람 · AI 창 이름, 직책 · 연차(대신 시니어 · 주니어 같은 역할 이름). 도구 이름(엑셀 · 구글 시트 · 노션 · 피그마)은 됩니다. 프로젝트 값은 설정 파일로.
3. **새 작성 규칙은 개인 메모리가 아니라 스킬에.** "앞으로 이렇게 해" 같은 규칙이 생기면 해당 스킬을 고칩니다. 개인 메모리는 다른 사람의 AI가 읽지 못합니다.
4. **고친 뒤 검사:** 고유 이름 검색 0건, 같이 쓰는 스킬과 내용이 겹치거나 어긋나지 않는지, 등록 파일 설명(description)이 내용과 맞는지.
5. **여럿이 쓰면 PR로 고칩니다.** 변경 이유를 남기고 시니어가 확인한 뒤 합칩니다. 스킬을 새로 만들면 1절 표 · 2절 그림 · 등록 파일을 함께 더합니다.
6. 고치기 전에 백업을 남깁니다(`_bak/` 폴더).
