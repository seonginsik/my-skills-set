# 화면설계서 작성 스킬 (피그마 기본)

> 이 파일은 `screen-spec-writing` 스킬입니다.
> 화면설계서(화면 배치 · 상태 장 · 번호 설명)를 새로 만들거나, 고치거나, 화면을 보관으로 옮기거나, 정리 · 점검할 때 이 파일을 먼저 읽고 따른다.
> 도메인 · 프로젝트와 관계없이 쓴다. 기본 도구는 피그마이고, 다른 디자인 도구여도 같은 규칙을 적용한다(도구 용어만 바꿔 읽음).
> 프로젝트마다 다른 값(파일 주소 · 페이지 목록 · 화면 ID 접두어 · 컴포넌트 이름 · 변수 이름 · 대응표 경로)은 **프로젝트 폴더의 `planning-config.md` › '화면설계'** 절에서 찾는다. 이 스킬에는 고유 이름을 적지 않는다.
> 같이 쓰는 스킬: 컴포넌트 페이지 관리 `figma-component-system` · 문구 `ux-writing` · 기능정의서 `spec-sheet-writing` · 단계 순서 `product-planning-process`

---

## 1. 한 장의 모양

한 장(프레임) = **머리글 + 화면 + 오른쪽 설명**.

| 부분 | 들어가는 것 |
|---|---|
| 머리글 | 페이지 · 화면 ID · 화면명 · 경로 · 기능 ID |
| 화면 | 실제 화면(정해진 화면 폭), 번호 표시(마커) |
| 오른쪽 설명 | 상태 칩(같은 화면의 다른 상태 장으로 가는 칩) · 번호 항목 · 공통 규칙 줄(S) · 미정 질문(가정값과 함께) |

- **화면 ID** = `접두어-영역-번호`, 상태는 뒤에 a · b · c(예: `XX-ORD-02a`). 같은 화면의 상태는 같은 번호에 글자만 바꾼다.
- **머리글 칸 규칙**
  - 페이지 = 그 장이 있는 페이지 이름(앞 번호 · 버전 빼고)
  - 화면명 = 장 이름에서 화면 ID를 뺀 것(`화면명 · 상태`)
  - 경로 = 화면 속 왼쪽 메뉴의 '대메뉴 > 소메뉴'(구분 기호는 '>'만)
  - 기능 ID = 그 화면이 쓰는 기능정의서 ID(뺀 기능 ID는 지움)
- 장을 옮기거나 새로 만들면 머리글 ↔ 장 이름 ↔ 왼쪽 메뉴를 대조한다.

## 2. 번호와 설명

- **번호 = 화면을 읽는 순서.** 위 → 아래, 두 칸 화면은 왼쪽 칸 → 오른쪽 칸, 확인 창에만 나오는 항목은 맨 뒤.
- **같은 화면의 모든 상태 장에서 같은 항목은 같은 번호.**
- **상태 장의 설명은 그 장에 보이는 번호만** 적는다(번호를 건너뛰어도 됨). 공통 규칙(S) 줄은 유지.
- **같은 구역 안에서 같은 설명은 한 장에만.** 여러 상태 장에 같은 항목 설명이 되풀이되면, 그 설명이 필요한 장(보통 기본 장) 하나에만 남기고 나머지 장에서는 설명 줄과 그 번호 표시를 함께 뺀다. 상태 장에는 그 상태에서 달라지는 것만 적는다. 화면을 이해하는 데 꼭 필요할 때만 중복을 허용한다.
- **비슷한 다른 화면도 같다.** 등록 · 수정처럼 항목이 같은 두 화면은 한 화면(보통 등록)에만 항목 설명을 두고, 다른 화면에는 그 화면에서만 달라지는 점(바꿀 수 없는 칸 · 저장 뒤 이동 · 막힘)과 '그 밖은 ○○ 화면과 같음' 링크만 둔다. 복사해 온 설명에 그 화면과 맞지 않는 문장이 남지 않게 한다.
- 확인 창 장은 배경 화면 번호를 빼고 창 안 항목만.
- 설명 문장은 '무엇이 · 언제 · 어떻게'를 짧게. 규칙을 새로 만들지 않고 기능정의서 · 정책에서 가져온다.
- 동작 시연(동작 웹 · 프로토타입)이 있으면 그 '설계 보기' 번호도 같게 맞춘다.
- **끝 검사:** 마커만 있는 번호 0 · 설명만 있는 번호 0 · 번호 중복 0 · 마커 겹침 0.

## 3. 페이지와 구역 배치

- **페이지 = 도메인(메뉴) 하나.** 맨 앞에 표지 · 공통 페이지, 맨 뒤에 컴포넌트 페이지.
- 페이지 안 맨 위 = **'목록 · 상태표' 구역**(화면 목록 · 상태표 · 미정 질문 장). 맨 아래 = **보관 구역**.
- 그 사이 구역 = **'대메뉴 › 소메뉴' 하나씩**, 왼쪽 메뉴 순서대로 위 → 아래. 구역 맨 위에 큰 이름표(메뉴 · 소메뉴 · '화면 N개 · 상태 장 M개').
- 구역 안 = **화면 하나가 한 줄.** 줄 순서는 사용 흐름(목록 → 등록 → 상세 → 수정 → 미리보기), 줄 안 상태 장은 a → z.
- 간격 기본값(설정 파일에서 바꿀 수 있음): 한 줄 최대 7장, 장 사이 120, 줄 사이 300, 구역 사이 400, 모든 구역 x = 0.
- 장이 어느 소메뉴인지는 화면 속 왼쪽 메뉴의 활성 항목으로 정한다. 메뉴 없는 화면(확인 창 · 완료 화면)은 여는 소메뉴에 둔다.
- 다른 페이지로 가는 버튼은 클릭 연결 대신 **페이지 이동 표시 컴포넌트**('↗ 페이지 · 화면 ID')를 버튼 옆에 둔다(프로토타입 클릭 연결은 페이지를 넘지 못함). 같은 페이지 안은 클릭 연결을 건다.
- 흐름 시작점은 소메뉴마다 첫 화면 하나.
- 구역 높이가 바뀌면 아래 구역 전체를 같은 거리로 민다. 끝에 **겹친 장 0** 검사.
- 표지 · 목록 장(페이지 구성 · 화면 목록)은 화면을 더하거나 뺄 때 함께 고친다.

## 4. 모양은 변수 · 스타일 · 컴포넌트로만

- 색은 색 변수, 크기 · 간격은 크기 변수, 글자는 글자 스타일, 버튼 · 입력 · 표 · 창 · 배지는 컴포넌트 인스턴스로만 넣는다. **값을 직접 칠하지 않는다**(디자인 가이드가 바뀌면 원본만 고쳐 전체에 반영되게).
- 컴포넌트 쓰는 법: 드롭다운은 입력 컴포넌트의 드롭다운 속성(글자 '▾' 금지), 여러 줄 입력은 여러 줄 입력 컴포넌트, 목록 화면은 작은 크기 변형(입력 · 탭 M, 표 칸 Compact).
- 화면이 '깨진다'는 말이 나오면 장마다 고치지 말고 원본(컴포넌트 · 변수)을 점검해 원인을 고친다.
- 없는 컴포넌트가 필요하면 `figma-component-system` 규칙으로 만들거나, 디자인 담당이 따로 있으면 요청하고 임시 컴포넌트에 `tmp/`를 붙인다(`team-collaboration-process`).

## 5. 입력 폼 규칙

- 칸 이름은 칸 이름 글자 스타일 하나로 통일(창 · 화면 모두).
- **'필수' · '선택' 배지는 한 폼 안에 필수와 선택이 섞여 있을 때만** 붙인다. 모두 필수면 배지 없음. '*' 표시는 쓰지 않는다. 둘 중 하나 이상이면 '하나 이상' 배지.
- 한 폼 = 같은 화면 ID + 같은 창 제목(상태마다 필수가 바뀔 수 있어 장 하나로 판단하지 않음).
- 필수 · 선택을 짐작하지 않는다. 기능정의서 · 정책에서 확인하고, 없으면 묻는다.

## 6. 화면을 빼거나 보관할 때

- 범위에서 뺀 화면은 지우지 않고 **그 페이지 보관 구역으로 옮긴다**(화면 ID 그대로).
- 함께 찾아 고칠 것: 다른 장에서 그 장으로 가는 클릭 연결 · 상태 칩 · 페이지 이동 표시, 레이어 이름의 '→ 화면 ID', 설명 · 화면 문구 · 예시 숫자, 목록 장 · 표지 · 왼쪽 메뉴 · 대시보드 같은 요약 화면, 머리글 기능 ID.
- **본문에 '1차 제외 · 없음 · 보관함' 같은 문구를 남기지 않는다.** 남은 기능만 설명한다. 흔적은 보관 구역 이름과 기능정의서 변경 기록에만.
- 화면설계 파일에는 변경 이력을 두지 않는다. 표지에 버전 번호만 올린다.
- 화면이 바뀌면 협업 채널의 '화면 변경 알림'에 한 줄(있으면, `team-collaboration-process`).

## 7. 화면 ID ↔ 노드 대응표

- 화면 ID마다 첫 상태 장(a)의 노드 ID · 페이지 · 머리글 기능 ID · 링크를 적은 대응표를 둔다(경로는 설정 파일). 기능정의서 '화면설계' 칸 링크가 이 표에서 나온다.
- 새 화면 ID 추가 · 첫 장 교체 · 화면 보관 때마다 표를 고치고, 기능정의서 담당에게 바뀐 줄을 알린다. 상태 장(b, c…)만 더할 때는 고치지 않아도 된다.

## 8. 만들 때 함정 (AI로 만들 때)

1. 글을 만들 때 글자 스타일을 바로 붙인다. 안 붙이면 도구 기본 글꼴이 들어간다. 컴포넌트 원본 안쪽 글도 센다.
2. 장을 복제하면 흐름 시작점도 복제된다 → 소메뉴마다 하나로 다시 맞춘다.
3. 장을 복제하면 칩 · 탭 · 버튼의 클릭 연결도 원본 장 그대로 따라간다 → 끝에 '이름의 → 화면 ID ↔ 실제 이동 장' 대조.
4. 스크립트가 중간에 오류 나면 그 호출 전체가 취소된다 → 다시 읽어 남은 것을 확인하고 다시 돌린다. 지울 노드를 틀로 다시 쓸 거면 지우기 전에 복제해 둔다.
5. 인스턴스를 크기 조절(rescale)하면 글자 크기가 바뀌어 글자 스타일 연결이 풀린다 → 폭만 바꾼다(resize).
6. 이미 변수가 연결된 칠에 기본색으로 다시 연결하면 기본색으로 보인다 → 변수의 실제 값을 넣은 칠에 연결한다.
7. 결과가 크면 나눠서 받는다(도구 반환 크기 제한).

## 9. 고치기 전 · 끝난 뒤

- 같은 파일을 다른 사람 · 창이 고칠 수 있다. 고치기 전에 알리고, 페이지(도메인) 단위로만 고친다. 같은 날 둘이 고치면 버전 번호를 서로 알린다.
- 견본 1장을 먼저 보여주고 OK를 받은 뒤 여러 장을 만든다.

## 완료 전 점검표

- [ ] 머리글 4칸(페이지 · 화면명 · 경로 · 기능 ID)이 규칙대로다
- [ ] 번호 ↔ 설명: 마커만 0 · 설명만 0 · 중복 0, 상태 장은 보이는 번호만
- [ ] 같은 구역 안 같은 설명이 여러 장에 되풀이된 곳 0(이해에 꼭 필요한 곳만 예외)
- [ ] 겹친 장 0, 구역 · 줄 순서가 메뉴 · 사용 흐름 순서
- [ ] 스타일 없는 글 0 · 기본 글꼴 0 · 직접 칠한 색 0
- [ ] 흐름 시작점 = 소메뉴 수, 클릭 연결 이름 ↔ 실제 이동 장 일치, 보관 장으로 가는 연결 0
- [ ] 뺀 화면은 보관 구역에, 본문에 '제외 · 없음' 문구 0
- [ ] 표지 버전 올림 · 대응표 · 목록 장 갱신, 기능정의서 담당에 바뀐 장 알림
